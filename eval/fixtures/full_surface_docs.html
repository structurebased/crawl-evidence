API reference / Audio

Transcribe audio

v2stable 99 languages

SENTINEL-DOCS-TEXT. The Transcribe endpoint accepts an audio file or a URL, runs it through the Vellum speech model and returns a transcript with speaker labels, word-level timestamps and a confidence score per segment.

Base URL https://api.example.com/v2 · Last updated October 30, 2026 · Changelog · OpenAPI

Overview

Transcription jobs can run synchronously for files under 25 MB and complete in roughly a quarter of the audio duration, or asynchronously for anything larger. The asynchronous path returns a job id immediately and delivers the transcript to a webhook you register, or you can poll the job until it reaches a terminal state.

The model is streaming-capable but this endpoint is batch only. For real-time captions use the Streaming transcription endpoint, which speaks WebSocket and returns partial hypotheses.

Base URL and versioning

Pin the major version in the path. We keep each major version for two years after its successor ships, and we never change a response shape inside a major version. Deprecations are announced in the changelog at least six months ahead and the Sunset header appears on deprecated routes.

Authentication

Send your secret key in the Authorization header. Keys are scoped to a project and carry a prefix that identifies the environment: vk_live_ for production, vk_test_ for sandbox. The sandbox runs the same models on fixture audio and writes nothing to your usage ledger.

Rotating keys

Create a second key, deploy it, then revoke the first. Keys can overlap for up to seventy-two hours, so a rolling deploy never has a window where no key works. Revocation is immediate and cannot be undone; usage already recorded under the key stays in your ledger.

import vellum

Create a transcription

POST /v2/transcriptions

Send multipart form data with an audio file, or JSON with an audio_url. The two are mutually exclusive. Files are streamed to object storage and deleted within twenty-four hours of the job finishing.

Language hints

Automatic detection picks one language for the whole file. Hints help when a recording switches languages, because the decoder can keep both acoustic models warm instead of committing early.

Pass the language you expect first. The model scores each hint against the first thirty seconds and reports which one it used in the response field detected_language.

For code-switched meetings, request diarization and leave language automatic; speaker turns are a stronger signal than a global hint in that case.

curl https://api.example.com/v2/transcriptions \
  -H "Authorization: Bearer $VELLUM_API_KEY" \
  -F audio=@call-2026-10-30.m4a \
  -F diarize=true -F timestamps=word

Audio input

We decode with ffmpeg before running the model, so container and codec support is broad. Anything ffmpeg 6 can read, we can transcribe. Sample rate is resampled to 16 kHz mono unless you pass preserve_channels.

Limits are per project and per region. Exceeding the request limit returns 429 with a Retry-After header; exceeding the concurrency limit queues the job instead of failing it.

Reading results back

Once a job finishes you read the result with the GET endpoint below. The response body is the same shape regardless of whether you submitted by URL, by upload or through the batch API, so one parser covers all three paths.

Retrieve a transcription

GET /v1/transcriptions/{id}

Read one completed transcription.

This call does not count against the rate limit. Transcriptions are available for 30 days after completion, then moved to cold storage for 12 months. Retrieve from cold storage takes up to two hours.

The response carries three groups of fields. Top level metadata identifies the job and its timings. The segments array holds the actual words with timestamps. Optional extras appear only when you asked for them with the include parameter, which keeps the default payload small enough to render in a browser without pagination.

Word level timestamps are interpolated from segment boundaries unless you submitted with word_timestamps set to true, in which case the whisper decoder emits them directly. The interpolated values are accurate to about 60 ms; direct values to about 20 ms. The timing_source field tells you which one you got.

SDKs and client libraries

Three official clients cover the languages most of our traffic comes from. Each client retries idempotent GETs three times with exponential backoff and surfaces rate limit headers as a typed exception.

Python, Node and Ruby

from vellum import Client, TranscriptionCreateParams

client = Client(api_key=os.environ["VELLUM_API_KEY"])

# Submit a URL. The SDK polls until completion by default.
transcript = client.transcriptions.create(
    source={"type": "url", "url": "https://example.org/audio/1031.wav"},
    model="whisper-large-v3",
    diarize=True,
    word_timestamps=True,
    webhook_url="https://example.org/hooks/vellum",
    poll_interval=2,
    timeout=600,
)

for segment in transcript.segments:
    print(f"{segment.start:8.2f}-{segment.end:8.2f} {segment.speaker}: {segment.text}")

# Verify the signature before trusting the payload
import hmac, hashlib, time

def verify(raw_body: bytes, headers: dict, secret: str) -> bool:
    expected = headers["vellum-signature"]
    signed = hmac.new(secret.encode(), raw_body, hashlib.sha256).hexdigest()
    timestamp, signature = expected.split(",", 1)
    if int(time.time()) - int(timestamp) > 300:
        return False  # replay window
    return hmac.compare_digest(f"t={timestamp},v1={signed}", expected)

Troubleshooting

The problems that generate the most support tickets, with the check we would run first. Every answer includes the log line or status field that confirms the diagnosis.

Common failures

The job stays queued for more than ten minutes
Your project is over its concurrent job limit. Check GET /v1/usage for concurrency.current. Queued jobs do not consume quota and are not billed until they start.
Audio decodes but the transcript is empty
The file is probably a video container with no audio track, or the track is at a sample rate ffmpeg cannot resample to 16 kHz. Run ffprobe -show_streams and look for a stream with codec_type=audio.
Diarization assigns every word to speaker 0
The recording is mono and under 30 seconds, below the diarizer's minimum separation. Split the file or set diarize to false and label speakers in post.
Language detection returns a confidence below 0.4
Code switching within the first 30 seconds confuses the detector. Pass language explicitly; the model then treats the other language as an accent rather than a switch.
Word timestamps drift after the first minute
The source file has a variable frame rate and its container timestamps do not match wall clock. Transcode with ffmpeg -vsync cfr and resubmit; the drift is in the source, not the decoder.
Webhook returns 500 and the job retries forever
Your handler is slower than three seconds or is not returning a 2xx. We retry 8 times over 24 hours with exponential backoff, then mark the delivery failed and expose it in /v1/webhooks/deliveries.
Rate limit returns 429 on the first request
Another integration is using the same API key. The 429 body includes limit_scope and the X-RateLimit-Reset header gives the epoch second when the bucket refills.
SRT output has overlapping cues
Two segments ended within 20 ms of each other, which is inside the SRT minimum cue duration. Set merge_cues to true in the export parameters to coalesce them.

The only breaking change in the v2 line is the speaker field shape in 2.0.0. Jobs submitted before June 2025 still return the old string labels, so a client that parses both shapes can read historical transcripts without migration.

Vocabulary and profanity filtering compose in a fixed order: the decoder sees the vocabulary list first, then the profanity filter runs on the emitted tokens. That order matters for domain terms that contain flagged substrings, and it is why a vocabulary entry for a medical device name survives the filter.

Webhook deliveries are at-least-once. Each event carries an id you should use as an idempotency key, and the deliveries endpoint lists the last eight attempts for any event with their response codes and elapsed times.

Cold storage retrieval is asynchronous and billed at the same rate as the original transcription. The retrieval job appears in the transcriptions list with status queued, and the original availability window restarts once the transcript is warm again.

The three official clients track the API independently. A client that is more than two minor versions behind still works against the current API, because the wire contract is versioned in the path, not the library.

The OpenAPI document at /openapi.json is generated from the same schema that validates incoming requests, so a generated client and the running API cannot drift apart.
