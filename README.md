# crawl-evidence

The independent, adversarially-verified evaluation harness for a web-extraction
engine. The engine is private. This repository holds the scorer, the fixtures,
the recorded outputs, and the methodology, so every number below can be
re-derived from files committed here.

## Honest scoreboard

Current numbers, run `eval_20261108_155615.jsonl`, 35 fixtures, scored offline:

| Metric | Value | Where it comes from |
| --- | ---: | --- |
| Fixtures | 35 | `eval/fixtures/` (34 HTML + 1 PDF) |
| Applicable recall | **99.7%** (292/293 cells) | `runner.applicable_summary` |
| Coverage, full set | **65.9%** (14 scored fields) | `runner.coverage_summary` |
| Crawl yield | **113.1** unique useful pages per 1,000 requests | `eval/report.py` |
| 100-URL slice, this engine | 70.0% coverage, 0.388 F1 | `compare.json` |
| 100-URL slice, Firecrawl API | 75.0% coverage, 0.516 F1 | the same 100 URLs |
| Completeness match | 35/35 | `eval/report.py` |
| Blocked rate | 8.6% (3/35) | `runner.applicable_summary` |
| Markdown integrity | 167/167 headings, 48/48 tables, 0 tag leaks | `runner.markdown_summary` |

Two rows need their caveats stated, because the scorer prints two numbers for
each of them:

- **Coverage.** The runner reports 65.9% over its 14 `SCORED_FIELDS`. The
  scorecard generated by `eval/report.py` prints `Avg field coverage (13 fields)
  = 64.0%`, because `report.py` uses a fixed 13-field set and drops
  `jsonld_link100`. Both figures recompute from the same shipped run. This repo
  publishes both instead of picking the flattering one.
- **Recall.** Applicable recall is a lower bound. The
  `source_applicable_fields` detector under-detects, so the fixture-ceiling
  coverage number is always printed beside it.

The Firecrawl row is the throttle-corrected re-run. An earlier attempt failed
81 of 100 requests with `RateLimitError`; that row is invalid and is not
published. `leaderboard-verification.md` records why and what was thrown out.

## What is in this repository

| Path | Contents |
| --- | --- |
| `eval/runner.py` | The scorer. Presence rules, applicable-cell recall, coverage floors, sentinel gates. Stdlib only. |
| `eval/report.py` | Regenerates the scorecard from `eval/results/`, and the yield metric from `learn/benchmarks/records.jsonl`. |
| `eval/classify.py` | Failure tagging for scored runs. |
| `eval/fixtures/` | 35 ground-truth pages, committed. |
| `eval/results/` | The recorded run, its classified copy, and the index-ready dump. |
| `eval/research/` | Methodology, the anti-gaming history, and the benchmark receipts. |
| `eval/research/scrape-evals-artifacts/` | `slice-100.csv` and `compare.json`, the data behind the 70/0.388 and 75/0.516 rows. |
| `learn/benchmarks/records.jsonl` | 8,162-request telemetry snapshot the yield metric reads (url, success, backend_used only). |
| `tests/` | Harness tests. Scorer tests run; live-engine tests skip with a stated reason. |
| `ruff.toml` | The lint policy, copied from the source repo. |

## The boundary

- The engine itself is private. `scripts/` is not in this tree, and no
  instruction in this repo can produce it.
- `eval/runner.py` imports the engine only inside `main()`, for a live run.
  Scoring, summaries, and report generation never import it.
- `eval/report.py` vendors the URL-dedup key it needs, so the yield recompute
  does not read `scripts/`.
- Every scoreboard number re-derives from files in this tree. None of them
  needs a live crawl or network access.

## Anti-gaming rules

The scorer refuses six moves that would inflate the score. All six are
documented in `eval/research/benchmark-fixed.md` and covered by tests in
`tests/test_eval_runner.py`.

1. Publishing applicable recall alone. Both numbers print on the same summary
   lines, so recall is always read beside fixture-ceiling coverage and blocked
   rate.
2. Counting blocked pages as coverage successes. Blocked fixtures are N/A in
   the applicable denominator, and blocked rate is its own gated line.
3. Dropping `json_ld` or `tables` from `SCORED_FIELDS`. Both stay, and a test
   asserts the field tuple is unchanged.
4. Scoring markdown on presence only. An empty shell scores zero. Leaked HTML,
   broken pipe tables, and unfenced code each score zero.
5. Treating iframe embeds as links without the recaptcha and turnstile
   exclusion. Wall frames would otherwise inflate `links`.
6. Padding fixtures with fields the engine already wins, or dropping
   `large_page` and `pdf_sample`. Both hard fixtures remain in the set.

Two structural rules sit underneath those six: floor constants are measured
baselines re-checked by tests, and the ground truth is committed fixtures and
a committed slice, not live pages, so it cannot drift between runs.

## Reproduce

All commands run from the repository root, offline, with a stock `python3`.

Scorecard from the shipped run:

```bash
python3 eval/report.py --output /tmp/scorecard.md
# **Fixtures:** 35
# | Completeness match | 35/35 |
# | Crawl yield (unique useful pages / 1,000 requests) | 113.1 |
```

The runner's own summaries:

```bash
python3 - <<'PY'
import json, sys
sys.path.insert(0, ".")
from eval import runner
rows = [json.loads(l) for l in open("eval/results/eval_20261108_155615.jsonl") if l.strip()]
print(runner.applicable_summary(rows))  # recall_pct 99.7, hits 292, total 293
print(runner.coverage_summary(rows))    # full_pct 65.9, full_n 35
PY
```

The slice numbers, recomputed from the per-task records rather than read from
the summary block:

```bash
python3 - <<'PY'
import json, statistics
d = json.load(open("eval/research/scrape-evals-artifacts/compare.json"))
for eng in ("crawl", "firecrawl"):
    tasks = list(d["tasks"].values())
    cov = [t[eng]["covered"] for t in tasks]
    f1 = [t[eng]["f1"] for t in tasks]
    print(eng, f"{100 * sum(cov) / len(cov):.1f}%", f"{statistics.mean(f1):.3f}")
PY
# crawl     70.0% 0.388
# firecrawl 75.0% 0.516
```

Tests and lint:

```bash
python3 -m unittest discover -s tests -v   # Ran 65 tests, OK (skipped=7)
ruff check . --config ruff.toml             # All checks passed!
```

The seven skips are deliberate: one live runner test, two full-results dump
tests, two tests that crawl a fixture to check the printed headline, one
markdown headline test, and one that checks `docs/CONTRACT.md`. Each skip
names the private engine or the private contract as its reason. Everything the
scorer can do offline runs.

## PR

The adapter behind the slice rows is
[martynasoxylabs/scrape-evals PR #1](https://github.com/martynasoxylabs/scrape-evals/pull/1),
titled "Add crawl_engine adapter: the /crawl engine, 70.0% coverage / 0.388 F1
on the 100-URL slice". The engine name in that PR and in the shipped research
docs is `crawl_engine`.

## Not in this repository

- The engine and its crawler scripts (`scripts/`).
- Campaign plans, ledgers, personal worklogs, and competitor strategy docs.
- Per-engine logs, diagnostics, and the benchmark workspace launcher.
- `docs/CONTRACT.md`, the full scoring contract. It stays in the private repo;
  the rules that gate this repository are the tests and the list above.
- Credentials and personal machine paths. The shipped research docs were
  scrubbed before commit.
